This project is an AI-powered Security Operations Center. Every 30 seconds, your pipeline fetches a batch of security logs from SAP, runs them through the ML model, and fires a webhook alert for any detected attacks. The Streamlit dashboard (which you don't own) connects to your API's `/metrics` and `/health` endpoints to display live data. ## 5. YOUR FILES IN DETAIL

### `src/api/main.py`

This is the FastAPI application — the single web process that runs on SAP BTP. It defines four HTTP endpoints: `/health` (is the app alive?), `/ready` (is HANA connected and is the model loaded?), `/predict` (score a batch of logs on demand), and `/metrics` (return MTTD numbers and counters as JSON). When the app starts, the `lifespan` function also launches the detection pipeline as a background `asyncio.Task` — so one process handles both web requests and continuous detection.

**Already built:** All four endpoints, lifespan with pipeline startup/shutdown, HANA pool initialization, schema migrations on boot.

**TODO for April 13:** Nothing in this file needs to change. The mock→live transition is handled entirely by environment variables. Once `SAP_API_URL` is set, the fetcher automatically switches from CSV to real API calls.

**Study:** FastAPI quickstart tutorial — understand what `@app.get("/health")` means, what Pydantic models do, and what `async def` gives you. Also read about Python `asyncio` — the lifespan uses it to run the pipeline concurrently with web requests.

### `src/api/schemas.py`

Defines every request and response shape using Pydantic `BaseModel` classes. For example, `HealthResponse` has fields for `status`, `mock_api`, `mock_webhook`, `mock_hana`. `PredictRequest` expects a list of `LogEntry` objects. The FastAPI framework uses these schemas to automatically validate incoming requests and generate the `/docs` page.

**Already built:** All schemas for all endpoints.

**TODO for April 13:** If the SAP API returns additional fields you want to expose, you may need to add them to the relevant schema. Otherwise, no changes needed.

**Study:** Pydantic documentation — understand `BaseModel`, `Field`, and how FastAPI uses them for automatic validation.

### `src/pipeline.py`

The orchestrator. `Pipeline.run_once()` executes one full detection cycle: OBSERVE (fetch logs) → ANALYZE (extract features) → DETECT (score with model) → RESPOND (fire webhooks, generate incident reports, save to database). `Pipeline.run_forever()` loops `run_once()` with `settings.poll_interval_seconds` (default 30) between cycles, with exponential backoff on errors and graceful shutdown on SIGTERM.

**Already built:** Full pipeline with retry logic, backoff, SIGTERM handling, metrics reporting.

**TODO for April 13:** Nothing needs to change. Watch the logs after setting `SAP_API_URL` — you should see `pipeline.run_once.done` logs every 30 seconds with `status: ok`, `logs: N`, `anomalies: N`.

**Study:** Understand the `asyncio.Event` pattern for graceful shutdown — the pipeline checks `stop_event` between cycles so it can exit cleanly when Cloud Foundry sends SIGTERM during a restart.

### `src/ingestion/sap_log_fetcher.py`

The OBSERVE phase. In mock mode (when `SAP_API_URL` is empty), it reads from a local CSV file. When the URL is set, it makes paginated async HTTP requests to the SAP API with retry logic. The fetcher returns a normalized DataFrame regardless of the source — downstream code never knows whether data came from a file or an API.

**Already built:** Mock CSV fallback, async HTTP with httpx, pagination, retry on 5xx errors, connection management.

**TODO for April 13:** Verify pagination works with the real SAP API. Check the logs for `fetch.page` entries. If the API returns an unexpected response format, coordinate with the Data Architect to update `src/ingestion/log_parser.py`.

**Study:** `httpx` documentation — it's like `requests` but supports async. Understand `async with` and `httpx.AsyncClient`.

## 10. IF SOMETHING BREAKS

**ERROR:** `uvicorn: error: no module named src.api.main`
**CAUSE:** You're not in the project root directory, or the virtual environment isn't activated.
**FIX:** `cd sap-threat-detector && source .venv/bin/activate && make api`

**ERROR:** `ModelNotFoundError: No trained model found in models/`
**CAUSE:** The pipeline started but no model has been trained yet.
**FIX:** Run `make train` in another terminal. The pipeline will pick up the model on the next cycle.

**ERROR:** `httpx.ConnectError` when fetching from SAP API
**CAUSE:** The SAP_API_URL is wrong, unreachable, or the API key is invalid.
**FIX:** Check `.env` for typos. Try `curl -H "Authorization: Bearer $SAP_API_KEY" "$SAP_API_URL"` to test the API directly.

**ERROR:** `cf push` fails with "Authentication failed"
**CAUSE:** CF credentials are wrong or expired.
**FIX:** Run `cf login` interactively to refresh. Update GitHub Secrets if credentials changed.

**ERROR:** Pipeline logs show `pipeline.run_forever.error` with `backoff_s: 60`
**CAUSE:** The pipeline hit an error and is backing off. The `error` field tells you what went wrong.
**FIX:** Read the error message. Common causes: SAP API down (wait and retry), model missing (run `make train`), HANA unreachable (check credentials).

## 11. GLOSSARY

| Term | Meaning |
|------|---------|
| **FastAPI** | A Python library that creates a web server with HTTP endpoints. You define functions like `async def health()` and FastAPI makes them accessible via URLs like `/health`. |
| **Endpoint** | A URL path on the server that responds to HTTP requests. Our app has four: `/health`, `/ready`, `/predict`, `/metrics`. |
| **asyncio** | Python's built-in library for running multiple things concurrently without threads. The pipeline and API share one process using asyncio. |
| **Lifespan** | A FastAPI feature that runs setup code when the app starts and cleanup code when it stops. We use it to start the pipeline and connect to HANA. |
| **Cloud Foundry (CF)** | SAP's hosting platform — you push your code and it runs on SAP's servers 24/7 without managing infrastructure yourself. |
| **BTP** | SAP Business Technology Platform — the umbrella platform that includes Cloud Foundry, HANA, and other SAP cloud services. |
| **manifest.yml** | A YAML file that tells Cloud Foundry how to run your app: memory, disk, start command, health check. |
| **Environment variable** | A key-value pair set outside your code (in `.env` locally, in CF/GitHub Secrets in production) that configures behavior without changing code. |
| **GitHub Secrets** | Encrypted variables stored in your GitHub repo settings. Used by CI/CD workflows to access credentials without putting them in code. |
| **CI/CD** | Continuous Integration / Continuous Deployment — automated pipelines that test your code on every PR (CI) and deploy it when merged (CD). |
| **Webhook** | An HTTP endpoint that another system calls to notify you of events. We POST to SAP's webhook when we detect an attack. |
| **Mock mode** | When external service URLs aren't set, the code automatically uses local fallbacks (CSV files, in-memory storage, logged alerts) so development works without real credentials. |
| **uvicorn** | The ASGI server that runs the FastAPI app. It listens on a port and forwards HTTP requests to your Python code. |
| **Health check** | An endpoint (GET /health) that Cloud Foundry polls to confirm the app is alive. If it returns non-200, CF restarts the app. |
| **Polling interval** | How often the pipeline runs a detection cycle. Default: every 30 seconds. Configurable via `POLL_INTERVAL_SECONDS` in `.env`. |
| **SAP_API_KEY** | A secret token that authenticates our app with the SAP security log API. Treat it like a password — never commit it to code. |
